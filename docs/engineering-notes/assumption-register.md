# Assumption register

These are claims to test, not facts to repeat as product validation.

| ID | Assumption | Why it matters | Current evidence | Next test | Status |
|---|---|---|---|---|---|
| A-001 | Applied ML teams regularly review notebook-based experiments before results are shipped or presented. | Without a recurring review event there is no natural place for ValidityCI. | Common workflow pattern; no customer evidence recorded yet. | Interview 10 applied ML engineers, reviewers, or consulting leads and collect recent examples. | Unvalidated |
| A-002 | Existing code review and experiment tracking do not adequately verify evaluation methodology. | The product must fill a gap rather than duplicate GitHub review, MLflow, or test libraries. | The architecture targets runtime evidence and counterfactuals that code review does not normally provide. | Compare the same flawed experiment against common review and tracking workflows. | Partially reasoned |
| A-003 | Users will accept containerized re-execution in exchange for stronger evidence. | The core product requires controlled execution. | The local example works; no external usability evidence. | Ask pilot users to run the image against a real, sanitized project and record setup time and blockers. | Unvalidated |
| A-004 | A customer-hosted runner is enough to address proprietary-data concerns. | B2B users may reject uploading code and data to a hosted service. | Declared-input staging keeps data local in the current design. | Conduct security reviews with teams that handle proprietary or regulated data. | Unvalidated |
| A-005 | High-confidence leakage and evaluation checks can be implemented with an acceptable false-positive rate. | Reviewers will abandon a noisy gate. | Local benchmarks distinguish clean and leaky holdouts plus clean and preprocessed-before-fit `GroupKFold` pipelines. A controlled group-split run also removes seeded entity overlap and reports the metric delta. A versioned policy limits blocking/high to directly confirmed runtime leakage; no external cases have been evaluated. | Expand with nested/repeated CV, search APIs, missing entities, custom splitters/transformers, and real sanitized notebooks. | Supported narrowly |
| A-006 | Reviewers value evidence and reproduction more than a natural-language explanation alone. | This is the main differentiation from generic AI review. | The report links the current finding to dataset statistics and notebook cells. | Compare evidence-first and explanation-first reports in user studies. | Unvalidated |
| A-007 | Two controlled runs are a useful early signal for uncontrolled randomness. | Repeated execution is the first reproducibility check. | The stable example matched across metrics, outputs, and environment. An unseeded benchmark produced a metric delta and reproducibility finding while its environment remained equal. | Expand the benchmark with harmless output variation, seeded parallel algorithms, and nondeterminism that does not change the primary metric. | Supported narrowly |
| A-008 | Teams can declare all required local inputs and dependencies. | The restricted runner exposes only declared files and a fixed package set. | The included example fits this model. | Try five real notebooks and categorize missing-file, package, service, and environment assumptions. | Unvalidated |
| A-009 | A CI gate is more valuable than a standalone report. | Recurring use and budget are more likely when validation is part of delivery workflow. | Product reasoning only. | Run pilots first as reports, then test whether teams ask for protected checks or approval history. | Unvalidated |
| A-010 | An AI investigator can improve prioritization without reducing factual reliability. | This is the main future AI-engineering component. | No agent exists yet; normalized metric artifacts provide one concrete evidence type it could query later. | Build a deterministic benchmark first, then require evidence citations and compare usefulness and unsupported-claim rates. | Unvalidated |
| A-011 | The initial buyer is an applied ML lead, consultancy, or model-risk reviewer rather than an individual student. | This affects integrations, pricing, and security requirements. | Plausible target profile; Georgia Tech provides convenient users but not necessarily buyers. | Separate usability interviews from buyer interviews and track willingness to pilot or pay. | Unvalidated |
| A-012 | The pain is expensive enough to justify adoption. | Technical interest alone does not make a SaaS business. | No commercial evidence recorded yet. | Ask about the last invalid experiment, its cost, current prevention effort, and budget owner. Avoid asking only whether the idea sounds useful. | Unvalidated |
